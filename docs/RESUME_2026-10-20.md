## Why it was stopped rather than left to sleep

The traces stage writes a problem that raises an exception as a permanent
`ok: false` row and never retries it. A CUDA error after the laptop wakes
would therefore enter the replication as failed problems. Shutting down
mid-problem is safe, as is a hard kill: no failure row is written, and an
incomplete last line is dropped and redone. **Sleep with the job running is
the one unsafe option.**

## Resume: one command

From the repository root, on this machine, plugged in, sleep disabled.

**First, quit OMEN Command Center** from the system tray. It holds about
570 MiB of GPU memory, which makes the model spill into system memory and
run 10–20× slower (D89). `resume_rep1.py` warns if any process holds GPU
memory, but it stops nothing.

```powershell
$env:PYTHONUTF8 = "1"
.venv\Scripts\python.exe scripts\resume_rep1.py
```

It runs, stopping at the first failure:
1. the traces stage (`generate_traces.py --config replication --no-entropy`)
   for the 169 missing problems, about 12–14 hours. Per-problem seeds make a
   resumed problem identical to an uninterrupted one;
2. `rep1_runbook.py`: ast, acts, baselines, nla, forcing (blocks of 2, 200
   re-forced), D75 confirmatory, D79 audit, each gated. Roughly 4–7 hours;
3. `post_rep1_queue.py --stage1`: D82 forcing and analysis on `main_nla240`,
   the rep1 secondaries, D82 on rep1, then Stage 1. Roughly 12–16 hours.

Completed work is never repeated. Traces, activations, verbalisations and
forced answers resume per item. Finished analyses refuse to overwrite and
are skipped. **The one exception:** reconstruction writes its file at the end,
so a reconstruction phase interrupted midway restarts that phase. The
verbalisations it reads are kept.

Logs: `runs/rep1/run.log`, `runs/rep1_runbook/`, `runs/post_rep1_queue/`.

## Pausing again

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\safe_stop.ps1
```

- **During the traces stage:** it stops the orchestrators, waits for the next
  trace to be flushed, and stops the stage.
- **During any other stage:** it reports what is running and stops nothing.
  You can wait for that stage to finish, or stop it with Task Manager, which
  is safe, because every stage resumes. Then run `resume_rep1.py` again.

**Shut down; do not sleep.** In any of these cases, to make sleep impossible
while running, use **Settings → System → Power → Sleep: Never** (when plugged
in).
