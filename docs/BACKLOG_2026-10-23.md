## Branch protection: enabled 2026-10-23 (D97) with the settings below

Enabled on 2026-10-23 through the API call below, at the researcher's
request, and verified with the read-back command (D97). Admin enforcement
is off, which leaves the documented emergency path. For a
single-maintainer repository, requiring an approving review would block
merging your own PRs. The recommendation is therefore a required status
check, without required reviews.

| setting | value | why |
|---|---|---|
| Require a pull request before merging | on; required approvals **0** | every change goes through a PR and its checks |
| Require status checks to pass | on: **`pytest`** (the `cpu-tests` workflow's job) and **`GitGuardian Security Checks`** | the CPU suite and the secrets scan become gates |
| Require branches to be up to date before merging | off (optional) | on would force a re-run after every merge; your choice |
| Block force pushes | on | history is never rewritten |
| Block deletions | on | `main` cannot be deleted |
| Do not allow bypassing the settings | your choice; leaving admin bypass on keeps an emergency path | — |

**Through the web interface:** Settings → Branches → Add branch ruleset
(or "Add classic branch protection rule") → target `main` → apply the
table.

**With the GitHub CLI**, as the repository owner (classic protection;
review first):
```
gh api -X PUT repos/Tejo0507/NLAutoencoders-AnswerStableTail/branches/main/protection \
  -H "Accept: application/vnd.github+json" --input - <<'JSON'
{
  "required_status_checks": {"strict": false,
                             "contexts": ["pytest", "GitGuardian Security Checks"]},
  "enforce_admins": false,
  "required_pull_request_reviews": {"required_approving_review_count": 0},
  "restrictions": null,
  "allow_force_pushes": false,
  "allow_deletions": false
}
JSON
```
